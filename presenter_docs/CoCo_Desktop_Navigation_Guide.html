1. The workspace at a glance

CoCo Desktop is an agentic IDE connected to your Snowflake account. The window is organized into panes you can show, hide, resize, and rearrange. A typical layout looks like this:

Side barFile Explorer
Database Explorer
Source Explorer
EditorSQL, Python, notebooks, YAML, Markdown — tabbed
PanelQuery results · Terminal · Output
CoCo ChatAsk, plan, build, and run with the AI agent

The activity bar on the far left switches which explorer is shown in the side bar. Drag pane borders to resize, and drag tabs to split the editor.

2. File Explorer

The File Explorer shows the folder (workspace) you have open on your local machine.

Open a project
Use File → Open Folder to choose a working directory. CoCo uses this folder as its context for reading and writing files.
Manage files
Create, rename, move, and delete files and folders. Right-click for context actions.
Git awareness
If the folder is a Git repository, changed files are highlighted so you can review what CoCo modified.
Tip: Put an AGENTS.md file at the root of your project to give CoCo standing instructions (naming standards, "always ask before running DROP", etc.). CoCo reads it automatically.

3. Database Explorer

The Database Explorer is your view into the connected Snowflake account.

  • Browse objects: expand databases → schemas → tables, views, stages, functions, and more.
  • Inspect: select an object to see its columns, data types, and details.
  • Connection context: confirm the active connection, role, and warehouse — only objects your role can access appear.
  • Hand off to CoCo: reference an object by its fully qualified name (DATABASE.SCHEMA.TABLE) in chat to ground the AI's answer in that object.

4. Editor

The Editor is the central, tabbed workspace for code.

TaskHow
Write and run SQLOpen or create a .sql file, then run the current statement or a selection against Snowflake. Results appear in the panel below the editor.
Work in notebooksOpen an .ipynb file to mix SQL, Python, and charts cell by cell.
Review AI changesWhen CoCo edits a file, open it in the editor to inspect the diff before you accept or commit.
Split viewDrag a tab to the side to compare two files, e.g. setup script and prompts.

5. CoCo Chat Session

The chat pane is where you collaborate with the CoCo agent in plain language. CoCo can explore your account, write and run SQL, edit files, and build apps — showing each step as it works.

Ask
"What tables contain customer orders?" · "Explain this query."
Build
"Create a dynamic table that aggregates daily sales." · "Build a Streamlit dashboard."
Fix
"Why did this query fail?" · "Optimize this warehouse's spend."

Working effectively

  • Modes: use Plan mode to agree on an approach before changes, then Agent mode to implement.
  • Approvals: CoCo asks permission before running commands or tools, depending on the approval mode you choose. Review SQL before approving anything destructive.
  • Context: mention files, objects, or paste errors directly in the prompt. Be specific about database, schema, role, and warehouse.
  • New session: start a fresh chat for an unrelated task to keep context focused.

6. Source Explorer

The Source Explorer (source control view) tracks changes in your project so you stay in control of what CoCo produces.

  • See every added, modified, or deleted file since your last commit.
  • Click a file to view a side-by-side diff of the changes.
  • Stage, discard, and commit changes — or ask CoCo in chat to "commit these changes" with a descriptive message.
Tip: Commit before asking CoCo for a large change. It gives you a clean checkpoint to compare against or roll back to.

7. Viewing and adding Skills

Skills are packaged expertise — instructions and workflows for a specific domain (for example semantic views, dynamic tables, cost analysis, Streamlit, data governance). When your request matches a skill, CoCo loads it automatically and follows its guided workflow.

View available skills

  • In the chat input, type / or $ to see the list of skills you can invoke, then pick one to run it directly (e.g. $semantic-view).
  • Or simply ask: "What skills do you have?" or "Which skill helps with dynamic tables?"
  • Skills come from several sources: bundled (ship with CoCo), user / profile (your own, stored locally), stage and catalog (shared in your Snowflake account), and plugins.

Add skills

OptionHow
Install from the catalogAsk CoCo: "Search the skill catalog for <topic>". It lists matching skills and plugins shared in your account and gives you an install link.
Create your ownAsk CoCo: "Create a skill that …" or "Capture this session as a skill." It scaffolds a SKILL.md with the workflow and triggers.
Install a pluginAsk CoCo to install a plugin from a local folder or a Git URL. Plugins can bundle multiple skills, agents, and MCP servers.
Share with your teamAsk CoCo to "share my skill to the catalog" so others in your account can find and install it.

8. Quick tips

  • Always confirm the active role and warehouse before running work.
  • Use fully qualified object names in prompts to avoid ambiguity.
  • Ask CoCo to write code to a file first, review it in the Editor, then execute.
  • Use the Source Explorer to review every change before committing.
  • Need help? Ask in chat: "Give me a guide to CoCo features".
