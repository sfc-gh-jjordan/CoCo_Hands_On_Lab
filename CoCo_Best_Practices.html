1. Keep prompts succinct & review code before running it

CoCo works best with a clear goal, the relevant context, and explicit constraints. Long, rambling prompts dilute intent and consume tokens; vague prompts force CoCo to guess.

Anatomy of a good prompt

  • Goal – what you want, in one sentence.
  • Context – the exact table, file, stage, or object (fully qualified).
  • Constraints – warehouse, role, naming standards, "don't modify X".
  • Output – where the result should go (a file, a table, a chart).

Less effective

"Can you look at my sales data and figure out what's going on and maybe fix the pipeline and also build a dashboard?"

More effective

"Write a SQL script in sql/top_customers.sql that returns the top 10 customers by revenue from SALES_DB.CORE.ORDERS for the last 90 days. Don't run it yet."

Always write code to a file first, then review, then run

Ask CoCo to create the code in a file for your review before executing. This gives you a checkpoint to catch wrong objects, destructive statements, or expensive queries, and leaves a reusable, version-controllable artifact.

Create the DDL and load script in scripts/load_customers.sql.
Do not execute anything. I'll review it first.

After review:

Looks good. Run scripts/load_customers.sql and show me the row counts.
Tips
  • Use Plan mode for multi-step or ambiguous work so CoCo proposes a plan you approve before it changes anything.
  • Keep CoCo's approval / permission mode set so that SQL execution and file writes require confirmation, especially in production accounts.
  • Ask CoCo to compile/validate SQL without executing when you only want a syntax check.
  • Iterate in small steps: one change, verify, next change.

2. One topic or task per chat session

Every message, tool result, and query output in a chat accumulates in the model's context window. Long sessions that wander across many topics become slower, more expensive, and less accurate: older details get summarized away, and unrelated context can confuse new requests.

Recommended workflow

  1. Start a chat for a single, well-scoped task (e.g. "build the staging tables").
  2. Save the work into files – SQL scripts, Python, notebooks, a short NOTES.md or README with decisions made.
  3. Review and test those files.
  4. Start a new chat for the next task, and point CoCo at the saved files instead of re-explaining history: 
    Read scripts/staging_tables.sql and NOTES.md. Now build the transformation
layer on top of those staging tables in scripts/transform.sql.
Signs it's time for a new session: you're switching topics, CoCo is repeating earlier mistakes, responses slow down, or the conversation has been summarized/compacted.

3. Referencing files, stages and database objects

Precise references are the single biggest driver of accurate results. Be explicit rather than descriptive.

WhatHow to reference itExample
Local files & foldersType @ in the chat to pick a file, or give a project-relative / absolute path@sql/load.sql, labs/lab1/README.md
Tables / viewsFully qualified DATABASE.SCHEMA.OBJECTSALES_DB.CORE.ORDERS
Stages@DB.SCHEMA.STAGE/path@RAW_DB.LANDING.FILES_STG/2026/10/
Semantic views, agents, search servicesFully qualified name + object type"the semantic view ANALYTICS.SV.SALES_SV"
Warehouse / role contextState them explicitly"Use warehouse COCO_WH and role ANALYST"
Selected code or terminal outputSelect text in the editor/terminal and ask about it, or paste the error"Explain the error in my last terminal command"

Navigation tips

  • Use the Snowflake catalog/object explorer in CoCo to browse databases, schemas and objects, then copy the fully qualified name into your prompt.
  • If you don't know where data lives, ask CoCo to search first: "Find tables related to customer churn" – then pick the right one before asking for SQL.
  • Ask CoCo to DESCRIBE or sample an object before writing complex logic against it.
  • Reference only the files that matter. Pointing CoCo at an entire large repo wastes context; pointing it at three relevant files is fast and accurate.
  • Open files in the CoCo editor with coco <path> from the integrated terminal.

4. Project instructions with AGENTS.md

A project instructions file is a Markdown file at the root of your project that captures standards, conventions and guardrails so you don't have to repeat them in every prompt. AGENTS.md is the primary instruction file for Cortex Code and is loaded automatically at the start of every conversation – no need to reference it in your prompts.

What to include

  • Project overview – purpose, key databases/schemas, folder layout.
  • Environment – default warehouse, role, dev vs. prod databases.
  • Standards – naming conventions, SQL style, comment/header requirements, testing expectations.
  • Never do – explicit guardrails.
  • Workflow – e.g. "write code to a file and wait for approval before executing".

Example

# AGENTS.md

## Project
Customer analytics pipeline. Source: RAW_DB.LANDING. Target: ANALYTICS_DB.CORE.
Folders: sql/ (DDL + DML), python/ (Snowpark), notebooks/, docs/

## Environment
- Warehouse: COCO_DEV_WH   Role: DATA_ENGINEER_DEV
- Work only in *_DEV databases unless told otherwise.

## Standards
- Fully qualify every object: DATABASE.SCHEMA.OBJECT
- snake_case for columns; UPPER_CASE for object names
- Every script starts with a header comment: purpose, author, date
- Use CREATE OR REPLACE only for views; use CREATE IF NOT EXISTS for tables

## Workflow
- Always write code to a file and wait for my review before executing.
- Prefer small, incremental changes. Summarize what changed at the end.

## Never
- Never run DROP, TRUNCATE, or DELETE without explicit confirmation.
- Never touch PROD databases or change grants/roles.
- Never hard-code credentials, tokens, or keys.
- Never use SELECT * against large tables without a LIMIT.
Keep it short and specific (roughly one to two pages). Because it's loaded into context, a bloated instructions file costs tokens on every request. Check it into source control so the whole team shares the same rules.

5. Using, creating and managing skills

Skills are packaged instructions (a SKILL.md plus optional scripts/reference files) that teach CoCo a specialized workflow. CoCo ships with many bundled skills (e.g. semantic views, Cortex Agents, dynamic tables, Streamlit, cost analysis) and loads them automatically when your request matches their description – only when needed, which keeps context lean.

Using skills

  • Automatic: just describe the task ("create a semantic view over ORDERS") and CoCo picks the matching skill.
  • Explicit: invoke a skill by name with /skill-name (or $skill-name) to force a specific workflow.
  • Discover: ask "What skills are available for X?" or browse/install from the skill catalog ("find a skill for data quality").

Creating a skill

Capture any repeatable workflow – your team's onboarding checklist, a standard pipeline pattern, a review process. The easiest path is to ask CoCo:

Create a skill from what we just did, called "load-landing-files",
that loads CSVs from a stage into a RAW table using our naming standards.

A minimal skill looks like:

load-landing-files/
  SKILL.md
  scripts/            (optional helpers)
  references/         (optional examples / templates)

--- SKILL.md ---
---
name: load-landing-files
description: Load CSV files from a landing stage into a RAW table. Use when the
  user asks to ingest, load, or COPY files from a stage. Triggers: load files,
  ingest CSV, copy into.
---
# Load Landing Files
1. Ask for the stage path and target table if not provided.
2. Infer the schema with INFER_SCHEMA and write DDL to sql/<table>_ddl.sql.
3. Write the COPY INTO statement to sql/<table>_load.sql.
4. Stop and wait for user review before executing.
Write a strong description. It's what CoCo reads to decide whether to load the skill, so include what it does, when to use it, and trigger phrases. Keep the body focused; move long examples into reference files that are read only on demand.

Managing skills

  • Scope: skills can be personal (user-level), project-level, or shared from a stage/catalog for your organization.
  • Share: ask CoCo to "share my skill" to publish it to your account's catalog so teammates can install it.
  • Audit & refactor: ask CoCo to "review/audit my skill" to tighten descriptions and trim oversized content.
  • Version control: keep custom skills in Git alongside your project; update them as standards evolve.
  • Plugins bundle multiple skills (and other components) for distribution – useful for team-wide toolkits.

6. Memory, context window and token efficiency

Everything CoCo sees – your prompts, file contents, query results, tool output, instructions files, and loaded skills – consumes tokens in a finite context window. Efficient usage means faster responses, lower cost, and better accuracy.

Limit large outputs

Ask for LIMIT 20, aggregates, or row counts instead of dumping thousands of rows. Ask for summaries of long logs.

Point, don't paste

Reference a file path rather than pasting a large file into chat; CoCo can read just the relevant portion.

Persist knowledge in files

Decisions, standards and progress belong in AGENTS.md, NOTES.md, or scripts – not only in chat history.

Use memory deliberately

CoCo can store persistent memories across sessions. Ask it to "remember" stable facts (preferred warehouse, coding style) and to update or remove stale ones. Keep memories short.

Scope your requests

"Fix the join in transform.sql line 40" beats "review my whole project".

Choose the right tool

Use semantic views / Cortex Analyst for business questions and catalog search for discovery instead of having CoCo scan many tables.

Context hygiene checklist

  • Start fresh chats per task (see section 2).
  • Keep AGENTS.md and skill files concise – they may be loaded repeatedly.
  • Avoid re-running the same large query; save results to a table or file and reference it.
  • Delegate broad exploration to sub-agents where available so the main conversation stays focused.
  • When a conversation is summarized, confirm key facts are captured in files before continuing.

7. Additional tips

Safety & governance

  • Use a least-privilege role and a dev database for CoCo work; CoCo acts with your Snowflake permissions.
  • Never paste secrets into chat. Use Snowflake secrets, key-pair auth, or environment variables.
  • Review every destructive or outward-facing action (DROP, GRANT, sharing, deployments) before approving.
  • Use a dedicated, appropriately sized warehouse with auto-suspend for CoCo sessions to control cost.

Quality

  • Ask CoCo to verify its work: run tests, validate row counts, or spot-check results.
  • Ask "what assumptions did you make?" when results look surprising.
  • When CoCo is wrong, correct it specifically ("the join key is CUSTOMER_ID, not ID") rather than restating the whole request.
  • Use Git: commit after each reviewed, working step so you can roll back easily.

Productivity

  • Use the ! prefix to run a shell command directly in the session so its output is available to CoCo.
  • Ask for visualizations inline ("chart revenue by month") for quick insight before building a dashboard.
  • Save prompts that work well into a team prompt library or turn them into skills.
